Fábrica de Serviços Cross-Platform

Um gerador de projetos visual em Lazarus (Free Pascal) no formato de Wizard de Produção com abas ocultas, gerando serviços de missão crítica para Windows (SCM) e Linux (Systemd) com zero overhead gráfico.

Modo Dual: Invisível + Console
Auto-Elevação UAC: Scripts .bat
Hot-Reload: Sinal SIGHUP Linux
Binário Puro: Zero LCL (~240 KB)
Fundamentos

Visão Geral & Filosofia de Arquitetura

Como a fábrica desacopla a complexidade de sistemas operacionais das regras de negócio.

Tradicionalmente, desenvolver serviços corporativos no Lazarus ou Delphi exigia lidar com particularidades intrincadas da API Win32 (como StartServiceCtrlDispatcher, RegisterServiceCtrlHandler e chamadas SCM) e com a estrutura do daemon Linux (sinais POSIX, systemd units e journalctl).

A Fábrica de Serviços resolve esse desafio através de um assistente interativo que gera uma arquitetura de 3 camadas estritamente desacoplada:

Wizard LCL (FabricaServicos.exe)
➔ GERA ➔
Projeto de Serviço Puro (FCL/RTL)
Camada 1: uServiceCore.pas (SCM / POSIX / Debug)
⬍
Camada 2: uWorker.pas (Thread de Negócio)
⬍
Camada 3: uConfig.pas (Singleton .ini)
🪟

Windows SCM Nativo

Integração direta com o Service Control Manager sem bibliotecas externas. Suporta auto-início, atraso de início e reinício automático em falha.

🐧

Linux Systemd Nativo

Unidade com Type=simple, Restart=always e captura direta de stdout/stderr pelo journalctl, além de captura do sinal SIGHUP.

⚡

Desacoplamento Visual Total

O executável final gerado não inclui LCL nem DLLs gráficas. Tamanho do executável compilado de aproximadamente 240 KB com início em milissegundos.

Passo a Passo

O Wizard em 5 Etapas de Produção

Fluxo com validação progressiva e garantia de consistência.

1
Etapa 1: Identificação & Diretórios Validação Pascal

Define o Nome do Serviço (obrigatoriamente um identificador válido sem espaços, ex: SyncVendasSvc), o Nome Amigável de Exibição, a Descrição e a Plataforma Alvo (Híbrido [Recomendado], Apenas Windows ou Apenas Linux).

2
Etapa 2: Arquétipo de Tarefa Regra de Negócio

Escolha o que o serviço executará. O Wizard injeta o esqueleto completo da thread de trabalho de acordo com o arquétipo escolhido (Pooling de BD, Monitor de Pastas, API HTTP, Agendador ou Fila).

3
Etapa 3: Frequência, Timer e Parâmetros Configuração .ini

Configure o intervalo de execução (em segundos, milissegundos ou minutos), ative a unit Singleton uConfig.pas para leitura de .ini e habilite o modo interativo /debug.

4
Etapa 4: Sistema Operacional & Infraestrutura SCM & Systemd

Defina o comportamento em caso de falha (Restart=always), usuário de execução Linux (ex: root ou www-data), dependências de inicialização (rede e bancos de dados) e ative a compilação com HeapTrc (-gh) para auditoria de memória.

5
Etapa 5: Resumo, Pré-Visualização e Geração Entrega Completa

Exibe um resumo completo das opções, permite pré-visualizar qualquer arquivo fonte gerado em tempo real com realce e gera o projeto instantaneamente, abrindo a pasta no Windows Explorer.

Especialização

Os 5 Arquétipos de Produção

Modelos arquiteturais prontos que resolvem problemas reais de automação empresarial.

1. Consulta / Pooling de Banco de Dados

Projetado para serviços que verificam periodicamente tabelas de filas ou tarefas em bancos como Firebird, PostgreSQL ou MySQL. Inclui controle de reconexão e espera responsiva via TEvent.

uWorker.pas — Trecho do Arquétipo de Banco de Dados 
procedure TServiceWorkerThread.Execute;
begin
  TServiceCore.LogMessage('INFO', 'Thread de trabalho iniciada. Intervalo: ' + IntToStr(FIntervalMs) + ' ms');
  while not Terminated do
  begin
    try
      ConnectAndProcessQueries; // Executa queries no banco
    except
      on E: Exception do
        TServiceCore.LogMessage('ERROR', '[DB-POOL] Erro na consulta de banco: ' + E.Message);
    end;

    // Aguarda o intervalo de forma responsiva (encerra imediatamente se chamado Stop)
    if FTermEvent.WaitFor(FIntervalMs) = wrSignaled then
      Break;
  end;
end;

2. Monitor de Diretório / Pastas

Monitora pastas de entrada (inbox) com teste de arquivo bloqueado (FileOpen em modo exclusivo) para garantir que um arquivo não seja lido antes de terminar a transferência.

uWorker.pas — Teste de Bloqueio de Arquivo 
function IsFileLocked(const AFileName: string): Boolean;
var
  FHandle: THandle;
begin
  // Testa se o arquivo ainda está sendo gravado ou copiado
  FHandle := FileOpen(AFileName, fmOpenRead or fmShareExclusive);
  if FHandle = THandle(-1) then
    Result := True // Arquivo bloqueado
  else
  begin
    FileClose(FHandle);
    Result := False; // Arquivo livre para processar
  end;
end;

3. API / WebService / Microserviço

Esqueleto para servidores HTTP, WebSockets ou RPC (ideal para integração com frameworks como Horse, Brook, fphttpapp ou mORMot). Inicia a escuta no Start e desfaz as conexões no Stop.

4. Agendador Diário / Backup

Garante a execução exata uma vez ao dia no horário configurado no .ini (ex: 02:00:00), com cálculo de virada de dia e prevenção contra execuções repetidas.

5. Loop Contínuo com Fila de Tarefas

Consumo de mensagens ou filas sincronizadas via TEvent, operando com zero busy-wait e resposta imediata sem consumo ocioso de CPU.

Parametrização

Gerenciador de Configuração (.ini) & SIGHUP

Padrão Singleton thread-safe com suporte a Hot-Reload no Linux.

O serviço gerencia suas configurações através de um arquivo .ini salvo no mesmo diretório do executável. O componente TAppConfig é thread-safe e protegido por TCriticalSection.

Recarregamento Dinâmico no Linux (Hot-Reload):
Ao enviar o sinal SIGHUP para o daemon (ex: pkill -HUP meuservico), o método ReloadConfiguration relê os valores do .ini e atualiza a frequência das threads sem necessidade de reiniciar o processo!

Orquestração

Orquestração de Dependências de Inicialização

Garantindo que os serviços dependentes subam na ordem correta.

No Windows, as dependências são registradas no Service Control Manager com o parâmetro depend= do utilitário sc.exe:

Comando sc.exe gerado no instalar.bat 
sc.exe create "SyncVendasSvc" binPath= "\"C:\Servicos\SyncVendasSvc.exe\"" start= auto DisplayName= "Serviço de Vendas" depend= Tcpip/LanmanWorkstation/FirebirdServerDefaultInstance

No Linux, as dependências são especificadas na seção [Unit] do arquivo de serviço do systemd:

meuservico.service 
[Unit]
Description=Serviço de Sincronização de Vendas
After=network.target network-online.target firebird.service
Wants=network-online.target
DevOps & Implantação

Scripts de Instalação com Auto-Elevação UAC

Instalação descomplicada sem necessidade de abrir prompts manuais como Administrador.

O arquivo instalar.bat gerado inclui uma rotina inteligente de detecção e auto-elevação de privilégios. Se você der um duplo-clique comum no arquivo, ele invoca a janela do UAC do Windows automaticamente:

instalar.bat — Rotina de Auto-Elevação UAC 
:: Auto-elevacao de Administrador (UAC)
net session >nul 2>&1
if %errorLevel% neq 0 (
    echo Solicitando privilegios de Administrador para registro do servico...
    powershell -Command "Start-Process '%~f0' -Verb RunAs"
    exit /b
)
Script Sistema Finalidade
instalar.bat Windows Auto-elevação UAC, registro no SCM via sc.exe, descrição e início automático.
desinstalar.bat Windows Auto-elevação UAC, parada do processo e remoção do serviço do SCM.
instalar.sh Linux Valida root/sudo, copia para /usr/local/bin, registra no systemd e habilita no boot.
remover.sh Linux Para e desabilita o serviço, remove unit e recarrega o systemd.
status.sh Linux Atalho rápido para systemctl status <servico>.
ver_logs.sh Linux Monitoramento contínuo em tempo real via journalctl -u <servico> -f -n 50.

Suporte

Perguntas Frequentes (FAQ)

Dúvidas comuns sobre compilação e deploy.

Por que o executável gerado não depende da LCL?

Serviços do Windows (SCM) e daemons do Linux não possuem desktop nem interface gráfica de usuário interativa. Depender de bibliotecas visuais como a LCL adicionaria consumo desnecessário de memória e dependências de servidor X/Wayland no Linux. Nossos serviços usam apenas a FCL e RTL, rodando com máxima leveza e segurança.

Como compilar o projeto gerado na linha de comando?

Basta rodar o utilitário lazbuild apontando para o arquivo .lpi gerado:
lazbuild "C:\Servicos\MeuServico\MeuServico.lpi" -B

Como recarregar configurações no Linux sem reiniciar o serviço?

Envie o sinal SIGHUP para o processo:
sudo systemctl kill -s HUP MeuServico ou sudo pkill -HUP MeuServico
O serviço manterá as conexões ativas e atualizará os valores do arquivo .ini instantaneamente.
